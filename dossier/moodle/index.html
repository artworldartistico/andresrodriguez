01 · Contexto

Una plataforma que no podía avanzar a producción

Petroworks necesitaba un centro virtual de formación (inducción, políticas, HSEQ). El proyecto ya existía, pero presentaba errores y no lograba avanzar.

Situación inicial

  • Moodle sobre Windows Server con IIS.
  • Errores 500 – Error interno del servidor al abrir actividades.
  • Actividades que no aparecían por incompatibilidades.
  • H5P sin cargar y SCORM con avisos de conexión inestable.
  • Sin estrategia de infraestructura, respaldos ni continuidad.

Mi rol

Dirección estratégica + arquitectura + implementación. Diagnostiqué la causa raíz, decidí la arquitectura destino, ejecuté la migración y entregué la documentación de operación.

  • Diagnóstico
  • Arquitectura
  • Migración
  • Seguridad SSL
  • UX / Login
  • Entrega
02 · Diagnóstico

La hipótesis inicial apuntaba a Moodle. Los datos, no.

Antes de tocar la aplicación revisé el entorno completo: sistema operativo, servidor web, PHP, base de datos, permisos y registros.

SíntomaHipótesis inicialHallazgo real
H5P “esperando a que se cargue”Plugin H5P dañadoPermisos de moodledata, FastCGI/IIS y combinación de versiones del stack
Error 500 en actividadesError en el cursoIncompatibilidades del entorno Windows/IIS con el LMS
Iconos e imágenes rotosURLs mal escritaswwwroot, caché y slasharguments en IIS
Warning en theme/adaptable/db/caches.phpTema corruptoPermisos del usuario del servidor web sobre el directorio
Plataforma lentaPoco hardwareCaché sin optimizar, límites de PHP y arquitectura sin plan de continuidad

Conclusión del diagnóstico: seguir “ajustando” Moodle sobre ese entorno era tratar síntomas. El riesgo real era la ausencia de una arquitectura preparada para compatibilidad, respaldos y continuidad operativa.

03 · Decisiones

Cuatro decisiones que cambiaron el proyecto

Cada decisión reduce un riesgo concreto. Se priorizó estabilidad y compatibilidad sobre “parchar”.

#Decisión¿Por qué?
1No continuar sobre Windows ServerCompatibilidad
2Migrar a Ubuntu (Apache + PHP + MySQL)Mayor estabilidad
3Mantener la misma versión de MySQLReducir riesgos durante la migración
4Instalar H5P únicamente después de validar el entornoEvitar falsos diagnósticos

Decisiones complementarias

  • HTTPS obligatorio: puerto 80 redirige con 301 a HTTPS; SSL en 443 y en el puerto alterno 18080 del cliente.
  • Límites de PHP definidos desde el inicio (memoria, subida de archivos) en lugar de reaccionar a errores.
  • Documentar todo el entorno para que el equipo del cliente pueda operarlo sin depender de mí.
  • Login propio alineado a la marca del cliente (“Somos Power / Somos Petroworks”).
04 · Implementación

Paso a paso de la migración y puesta en marcha

Los valores sensibles (usuarios, claves, IPs, rutas de llaves) se omiten o se reemplazan por marcadores.

Paso 1 · Verificar el servidor

Línea base de recursos y servicios antes de instalar nada.

bash · línea base
# Recursos
free -h && nproc && df -h && lscpu
# Sistema y versiones
uname -a && lsb_release -a && php -v
# Servicios y salud de Apache
sudo systemctl status apache2
sudo apache2ctl configtest          # Debe responder: Syntax OK
# Logs en vivo
tail -f /var/log/apache2/error.log

Paso 2 · Base de datos

Misma versión de MySQL que el origen para minimizar riesgo. Se restaura la base de datos y se valida el acceso del usuario de aplicación.

bash · acceso y validación
mysql -u USUARIO_MOODLE -h localhost -p
mysql> SHOW DATABASES;
mysql> USE moodle_petroworks;
mysql> SHOW TABLES;

Paso 3 · PHP: extensiones y límites

php.ini
extension=pdo_mysql
memory_limit = 512M        ; se subió 128M → 256M → 512M según el error
post_max_size = 100M
upload_max_filesize = 100M

Paso 4 · Apache: HTTPS, puertos y redirección

/etc/apache2/ports.conf
Listen 80
<IfModule ssl_module>
    Listen 443
    Listen 18080
</IfModule>
sites-available/moodle-ssl.conf
<IfModule mod_ssl.c>
  <VirtualHost *:443 *:18080>
    ServerName apps.tudominio.com
    DocumentRoot /var/www/html/moodle-petroworks
    SSLEngine on
    SSLCertificateFile      /etc/apache2/ssl/certificado.crt
    SSLCertificateKeyFile   /etc/apache2/ssl/llave.key
    SSLCertificateChainFile /etc/apache2/ssl/cadena.crt
    Header always set Strict-Transport-Security "max-age=31536000"
    <Directory /var/www/html/moodle-petroworks>
      AllowOverride All
      Require all granted
    </Directory>
    ErrorLog  ${APACHE_LOG_DIR}/moodle-petroworks_error.log
    CustomLog ${APACHE_LOG_DIR}/moodle-petroworks_access.log combined
  </VirtualHost>
</IfModule>

<VirtualHost *:80>
  ServerName apps.tudominio.com
  RewriteEngine On
  RewriteCond %{HTTPS} off
  RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</VirtualHost>
bash · habilitar y comprobar
sudo a2enmod ssl rewrite headers
sudo a2ensite moodle-ssl.conf 80-default.conf
sudo apache2ctl configtest && sudo systemctl reload apache2

sudo lsof -i :443 ; sudo lsof -i :18080
sudo netstat -tuln | grep 18080
openssl s_client -connect apps.tudominio.com:18080

Paso 5 · Archivos y permisos

bash
sudo chown -R www-data:www-data /var/www/moodledata
sudo chmod -R 755 /var/www/moodledata
# Tras migrar: limpiar cachés
sudo rm -rf /var/www/moodledata/cache/* /var/www/moodledata/localcache/*
php admin/cli/purge_caches.php

Paso 6 · Validar H5P (solo con el entorno estable)

Con el stack validado se instala/habilita H5P y se prueba con una actividad simple (cuestionario) antes de cargar contenido real. Así se evita atribuirle al plugin un fallo que no es suyo.

05 · Experiencia

Login personalizado con identidad de marca

Una página de acceso propia que envía el formulario al login nativo de Moodle, sin tocar el núcleo.

  • Formulario que apunta a ../login/index.php (autenticación nativa de Moodle).
  • Alerta de credenciales inválidas leyendo ?errorcode=3 de la URL.
  • Mostrar/ocultar contraseña, “Recordar nombre de usuario” y enlace de recuperación.
  • Animación “Somos Power / Somos Petroworks”, parallax y texto con efecto de escritura.
  • Galería de videos institucionales con reproducción en cadena y arrastre táctil.
  • Alojado en una carpeta propia dentro de Moodle: /moodle-petroworks/login-petroworks/.
login · alerta por errorcode
document.addEventListener("DOMContentLoaded", () => {
  const params = new URLSearchParams(window.location.search);
  if (params.get("errorcode") === "3") {
    const box = document.createElement("div");
    box.className = "alert alert-danger";
    box.setAttribute("role", "alert");
    box.innerText = "Acceso inválido. Por favor, inténtelo otra vez.";
    document.getElementById("alertContainer").appendChild(box);
  }
});

07 · Troubleshooting & resolución

Los fallos que encontré y cómo los resolví

Cada incidencia está documentada con síntoma, causa, solución y verificación. Es la parte más útil para quien opere la plataforma después.

01H5P se queda en “esperando a que se cargue”
SÍNTOMA
Las actividades H5P no terminaban de cargar en Moodle sobre Windows Server.
CAUSA
Entorno IIS/FastCGI con permisos de moodledata y combinación de versiones que no sostenían H5P. El plugin no era el problema.
SOLUCIÓN
Migrar a Ubuntu + Apache + PHP + MySQL, validar el entorno y solo entonces habilitar H5P.
VERIFICACIÓN
Actividad H5P simple y luego contenido real cargando sin esperas.
02Error 500 y aviso del reproductor SCORM
SÍNTOMA
500 – Error interno del servidor en actividades y aviso de “conexión inestable” en SCORM.
CAUSA
Errores del servidor que el reproductor interpreta como pérdida de conexión.
SOLUCIÓN
Revisar registros y estabilizar el stack. Con Apache y PHP corregidos desaparece el aviso.
VERIFICACIÓN
Seguimiento de progreso guardado sin avisos.
bash
tail -f /var/log/apache2/error.log
sudo journalctl -xeu apache2.service
grep -i alert /var/log/apache2/error.log
03Imágenes e iconos no cargan tras migrar
SÍNTOMA
Los hipervínculos estaban bien, pero las imágenes e iconos no aparecían.
CAUSA
moodledata incompleto o con permisos incorrectos, $CFG->wwwroot distinto al dominio real, contenido mixto HTTP/HTTPS y caché desactualizada.
SOLUCIÓN
Copiar completo moodledata, corregir wwwroot con https, ajustar propietario a www-data y purgar cachés.
VERIFICACIÓN
Abrir la URL de una imagen directamente y revisar la consola del navegador.
04Warning: theme/adaptable/db/caches.php
SÍNTOMA
Failed to open stream al incluir caches.php del tema.
CAUSA
Permisos del usuario del servidor web sobre el directorio del tema o archivos faltantes.
SOLUCIÓN
Corregir permisos y, si falta el archivo, reinstalar/actualizar Adaptable.
VERIFICACIÓN
Recarga sin warnings con depuración activada.
05Error de base de datos y límites de PHP
SÍNTOMA
Error de conexión a la base de datos y fallos al procesar actividades pesadas.
CAUSA
Extensión pdo_mysql deshabilitada y memory_limit de 128M insuficiente.
SOLUCIÓN
Habilitar extension=pdo_mysql; subir memoria a 256M y luego a 512M; fijar post_max_size y upload_max_filesize en 100M.
VERIFICACIÓN
php -m | grep -i pdo_mysql y reinicio de Apache.
06Redirección HTTP → HTTPS y SSL en puerto 18080
SÍNTOMA
“El fichero o directorio no existe” al configurar los sitios y el sitio no respondía por SSL en el puerto alterno.
CAUSA
Archivos de sitio sin habilitar, módulos ssl/rewrite inactivos y puerto 18080 no declarado dentro de ssl_module.
SOLUCIÓN
Habilitar módulos y sitios, declarar Listen 18080 en ports.conf y forzar HTTPS con regla 301 en el puerto 80.
VERIFICACIÓN
apache2ctl configtest, lsof -i :18080 y openssl s_client.
07Plataforma lenta
SÍNTOMA
Tiempos de respuesta altos en la plataforma instalada en el servidor.
CAUSA
Caché y sesiones sin optimizar, límites de PHP bajos y falta de monitoreo.
SOLUCIÓN
Ajustar PHP, purgar cachés, limpiar sesiones antiguas y monitorear con top, free -h y df -h.
VERIFICACIÓN
Recursos estables bajo carga normal de usuarios.
08La alerta del login desaparecía tras redirigir
SÍNTOMA
La alerta salía, pero al redirigir con errorcode=3 se perdía.
CAUSA
La alerta se creaba en el envío y no después de la redirección.
SOLUCIÓN
Leer errorcode de la URL al cargar la página y renderizar la alerta en un contenedor bajo el formulario.
VERIFICACIÓN
Credenciales incorrectas muestran el aviso; correctas inician sesión.
09Banner de cabecera cubría toda la pantalla
SÍNTOMA
La cabecera tapaba la interfaz, bloqueaba la configuración y obligó a reiniciar la máquina virtual.
CAUSA
Posición absoluta con desplazamiento negativo y un @media escrito dentro de un style en línea, que no es válido.
SOLUCIÓN
Mover los estilos al CSS personalizado del tema con media queries reales y alturas adaptables.
VERIFICACIÓN
Pruebas en escritorio y móvil sin solapamientos.
10Importación CSV y calificación máxima
SÍNTOMA
“No hay suficientes columnas” al importar usuarios y no se podía fijar calificación máxima 10.
CAUSA
CSV con delimitador o encabezados incorrectos; categoría del libro de calificaciones con bloqueos.
SOLUCIÓN
Normalizar columnas y delimitador del CSV; quitar bloqueos o crear una categoría nueva con máximo 10.
VERIFICACIÓN
Importación completa y ponderaciones correctas.
08 · Operación y entrega

Entrega documentada, sin dependencia de una sola persona

El cliente recibió un manual operativo del servidor para diagnosticar y mantener la plataforma.

Qué incluye la entrega

  • Comandos de recursos, versiones, logs y estado de servicios.
  • Configuración de Apache, puertos y SSL.
  • Acceso y validación de la base de datos.
  • Parámetros de PHP y permisos.
  • Personalización del tema y del login.

Gestión de secretos

Las credenciales no se publican ni se versionan.

  • Se entregan por canal seguro al responsable del cliente.
  • Recomendado: rotar claves tras la entrega y usar un gestor de contraseñas.
  • Este dossier solo usa marcadores.

La tecnología rara vez falla por una sola aplicación. Con frecuencia, el problema está en las decisiones de arquitectura que la sostienen.
